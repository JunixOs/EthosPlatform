4. JWT
============================================================
✅ SAFE — `JWT_SECRET` se lee exclusivamente de `process.env['JWT_SECRET']`
en LoginUseCase.ts (firma) y authMiddleware.ts (verificación). Ambos casos
lanzan un error explícito si la variable no está definida — no hay ningún
valor por defecto hardcodeado que pudiera usarse como secreto débil.
Además, el middleware valida la sesión contra la base de datos en cada
request (no solo el JWT), permitiendo invalidar tokens en logout — ver
BUGS_ENCONTRADOS.txt de una sesión anterior.

============================================================
5. CORS
============================================================
✅ SAFE — apps/backend/src/app.ts configura
`cors({ origin: process.env['FRONTEND_URL'] ?? 'http://localhost:16000', credentials: true })`.
El origin es restrictivo (no `*`), toma el valor real de `.env`
(`FRONTEND_URL=http://localhost:16000` en este entorno). Se corrigió en esta
sesión el valor de fallback hardcodeado (antes `5173`, el puerto por
defecto de Vite, que no coincidía con el puerto real configurado en este
proyecto — 16000, ver apps/frontend/vite.config.ts). No era explotable
(`.env` siempre lo sobreescribe) pero podía confundir a quien leyera el
código o corriera sin `.env`.
